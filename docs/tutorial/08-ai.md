# 8. Artificial intelligence: rivals that sail like sailors

## Learning objectives

- Structure an agent as **perceive → decide → act**, using the same controls as the player.
- Steer with a **proportional controller** and a slew-rate limit.
- Make discrete decisions (tack or not?) with **hysteresis** and **cool-down timers**.
- Predict collisions with the **closest point of approach** between two moving objects.

## 8.1 Fair rivals

In many games the computer opponents cheat: they ignore physics, or know things the player cannot. FairWind's rivals are fair by construction. `helm_ai` produces exactly the same three outputs a human produces with the buttons:

- a **rudder** angle (−100…100);
- a **sheet** setting (0–90° eased);
- a **kite request** (none, spinnaker, gennaker).

The same `update_rig` and `sail` functions of Chapter 6 then move the AI yachts. Anything the AI achieves, the player can achieve.

The tools reuse this symmetry. `tools/autopilot.h` asks `helm_ai` what it would do with the *player's* yacht, and presses the buttons a human would press to follow it. The host renderer and the profiler race the player's yacht with it.

## 8.2 Perceive, decide, act

`helm_ai` runs once per frame for each computer yacht and follows the classic agent structure:

1. **Perceive**: where is the next target, where is the wind, where are the other boats?
2. **Decide**: choose a desired heading `want`, a sheet and a kite.
3. **Act**: move the rudder towards the desired heading.

The *target* depends on the phase of the race, which is itself a small state machine:

| Phase | Target |
|---|---|
| Before 2 min, box closed | a holding point outside the line, then luff (sails eased, nearly stopped) |
| Box open, not entered, still below the line | a point above the line: go back and cross it properly |
| Box open, not entered | a point inside the box on its own side: crossing the line enters the box |
| In the box, too early | a waiting point deep in the box |
| In the box, time to go | a point on the line, speed metered with the sheets |
| After the gun, not yet valid | dip back below the line |
| Racing | 18 m to the right of the next mark, so the mark is left to port |
| Last leg | through the middle of the finish line |

## 8.3 Steering: a proportional controller

Given the desired heading, how much rudder? The simplest controller is **proportional**: the rudder angle is proportional to the heading error, limited to the rudder's range:

```c
err    = BAM2DEG((int16_t)(want - b->heading));        /* degrees, signed */
target = clamp(err * 5 + (int)(rnd() % 3) - 1, -100, 100);
slew_rudder(b, target, 10 * frame_ms / 16);
```

- The **gain** 5 means a 20° error gives full rudder, and small errors give gentle corrections.
- `rnd() % 3 - 1` adds ±1 of noise: a human helmsman is never perfectly still.
- `slew_rudder` limits how fast the rudder can move, like a real arm on a real tiller. That is a **slew-rate limit**, and without it a proportional controller can oscillate from side to side.

This is the first control loop most engineers ever build. More advanced controllers (PI, PID) add terms for accumulated and changing error. You will meet them in a control-systems course.

## 8.4 Upwind and downwind: velocity made good

A yacht cannot sail straight to a mark that is upwind: the no-go zone is ±28° from the wind. It must **beat**, zig-zagging on alternate tacks. The best angle is the one that maximises the **velocity made good** (VMG), the component of the boat's velocity towards the wind:

```
VMG(θ) = v(θ) · cos θ
```

From the polar (Chapter 6) in 12 knots: at 40° the boat does 7.2 kt and VMG = 5.5 kt; at 52° it does 8.1 kt but VMG = 5.0 kt. So pointing higher is better, down to about 40–42°. Downwind the same trade-off gives about 158°. The AI therefore sails at `twd ± 42°` upwind and `twd ± 158°` downwind, and the only question left is **which tack**.

```c
static uint16_t vmg_heading(boat_t *b, uint16_t brg, int angle) {
    uint16_t hs = (uint16_t)(twd - DEG(angle));        /* starboard-tack heading */
    uint16_t hp = (uint16_t)(twd + DEG(angle));        /* port-tack heading      */
    uint16_t cur = b->ai_tack > 0 ? hs : hp, oth = b->ai_tack > 0 ? hp : hs;
    int32_t cc = fcos((uint16_t)(cur - brg));          /* how well each tack      */
    int32_t co = fcos((uint16_t)(oth - brg));          /* points at the target    */
    int headed = angle < 90 && wind_shift_deg() * b->ai_tack <= -5;
    if (wind_t - b->ai_last_tack >= 25 &&              /* cool-down: 25 s         */
        (co >= layline_cos[b->team & 3]                /* 1. on the layline       */
         || co > cc + 4000                             /* 2. other tack far better */
         || (headed && co > 0)                         /* 3. headed by 5 degrees  */
         || near_edge(b, cur))) {                      /* 4. running out of water */
        b->ai_tack = (int8_t)-b->ai_tack;
        b->ai_last_tack = wind_t;
        cur = oth;
    }
    return cur;
}
```

The four tacking reasons are exactly what a coach teaches:

1. **Layline.** When the *other* tack points (almost) straight at the mark, `cos` is close to 1. Each team uses a slightly different threshold (5°–11° of overstanding), so the fleet spreads out realistically.
2. **Wrong side.** The current tack points away from the mark by a lot (a cosine difference of 4,000/16,384 ≈ 0.24).
3. **Tack on the headers.** A wind shift of 5° or more that makes the current tack worse is a *header*. The other tack is then *lifted*, and switching gains distance. This rule makes the AI react to the wind shifts of Chapter 5.
4. **Edges.** Never sail out of the race area.

### Hysteresis again

Why the 25-second **cool-down**, and why *thresholds* rather than "tack whenever the other tack is better"? Near the middle of the course both tacks are almost equally good, and the "better" one flips with every small wind oscillation. An AI that tacked on every flip would tack continuously, and each tack costs speed (Chapter 6). The cool-down and the thresholds are **hysteresis**: they require a clear advantage before a decision is changed, and hold the decision for a while once made.

## 8.5 The timed start

The start is the hardest skill in match racing: be at full speed on the line exactly at the gun. The AI uses the **time-distance** method taught to real crews:

```c
int32_t vcl = (int32_t)polar_speed10(45, tws10) * 5144 / 100 * 9 / 10;  /* close-hauled, mm/s, 90% */
d = distance to its point on the line;                                  /* metres */
if (start_clock > d * 1000 / vcl + (slow ? 14 : 4) + 2 * slot + 6)
    /* too early: go (or stay) deep in the box and wait, sails eased */
else {
    /* go: aim at the line, and meter the speed */
    vreq = d * 1000 / (start_clock - 1);                  /* speed needed to arrive at the gun */
    ease = vreq < vcl ? 18 * (vcl - vreq) / vcl + 2 : 0;  /* degrees of extra sheet */
    if (b->y > -12000 && start_clock > 3) luff = 1;       /* 12 m from the line: hold */
}
```

The time needed is the distance over the close-hauled speed, plus an allowance to accelerate: 14 s from a standstill, 4 s if already moving. It also includes a small per-boat offset so that the rivals do not arrive in a row. On the way in, the AI computes the speed that would bring it to the line *exactly* at the gun. If that is less than its full speed it **eases the sheet** by up to 18° past the optimum, which reduces drive through the trim model of Chapter 6. It is a speed controller made with the sail, as real crews do.

In the harness, all three AI yachts start within 23–65 seconds of the gun on every course. Good, but not perfect, and room for your improvements (see the exercises).

## 8.6 Seeing other boats: closest point of approach

To avoid collisions the AI must predict where the other boats *will* be. For two boats moving in straight lines, the **relative position** is **r** (from us to them) and the **relative velocity** is **w** = v_them − v_us. The distance between them at time *t* is |**r** + **w**t|, which is smallest at

```
t* = − (r · w) / (w · w)
```

(Differentiate |**r** + **w**t|² with respect to *t* and set it to zero.) The **closest point of approach (CPA)** is **r** + **w**t*. The code:

```c
w2 = wx * wx + wy * wy;                    /* w · w (decimetres/s squared) */
if (w2 < 4) continue;                      /* almost no relative motion     */
t  = -(rx * wx + ry * wy) / w2;            /* seconds to the CPA            */
if (t <= 0 || t > 25) continue;            /* diverging, or far in future   */
cx = rx + wx * t;  cy = ry + wy * t;       /* where they will be            */
if (cx * cx + cy * cy > 250 * 250) continue;          /* will pass > 25 m apart */
if (!gives_way(b, o, &head_up) &&
    (cx * cx + cy * cy > 120 * 120 || t > 8)) continue; /* our right of way, not imminent */
return (uint16_t)(want + (head_up ? DEG(20) : -DEG(30)) * b->tack);  /* manoeuvre */
```

`gives_way` encodes the keep-clear rules of Chapter 7 from the AI's point of view: port gives way to starboard, clear astern gives way, windward gives way. The give-way boat either **bears away** 30° to pass astern (a *duck*) or, if it is the windward boat, **heads up** 20°. The right-of-way boat holds its course, as the rules require, unless contact is imminent (closer than 12 m within 8 s). Then Rule 14 obliges it to avoid the collision too.

This is the same CPA computation used by ship collision-avoidance systems (ARPA radars) and by air-traffic controllers.

## 8.7 The kites

The kite decision looks at the angle of the current leg and of the next one:

```c
static uint8_t kite_for(int rel) {         /* rel: leg bearing relative to the wind, degrees */
    return (uint8_t)(rel >= 118 ? KITE_SPIN : rel >= 68 ? KITE_GENN : KITE_NONE);
}
```

Before a mark whose next leg needs no kite (the leeward mark before a beat) the AI drops the kite 110 m early, because a drop takes 12–19 s (Chapter 6). After a rounding it hoists only once the boat has actually borne away: a spinnaker set while still pointing upwind would slow the boat.
